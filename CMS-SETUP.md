# Подключение блога PRIME

Код редактора и интеграция Supabase готовы. Публичный URL/ключ, предоставленные владельцем, сохранены **только в локальном `.env`**. Проверка соединения прошла; Supabase вернул `PGRST205`: таблица `public.posts` ещё не создана. Поэтому `VITE_CMS_ENABLED=false`. Данные в удалённой базе не изменялись.

## Однократная настройка владельцем

1. Откройте SQL Editor своего проекта Supabase и выполните весь файл `supabase/migrations/202609190001_cms.sql`.
2. В Authentication → Users создайте редактора с вашим email и сильным паролем. Публичная регистрация для CMS не нужна — отключите signup. Пароль и service-role key нельзя добавлять в код или `VITE_*`.
3. Скопируйте UUID созданного пользователя и выполните в SQL Editor:

```sql
insert into public.prime_editors(user_id)
values ('UUID-СОЗДАННОГО-ПОЛЬЗОВАТЕЛЯ')
on conflict do nothing;
```

4. В локальном `.env` и Environment Variables проекта Vercel задайте:

```dotenv
VITE_SITE_URL=https://primemobdetail.pl
VITE_SUPABASE_URL=<URL вашего проекта>
VITE_SUPABASE_PUBLISHABLE_KEY=<публичный publishable или anon key>
VITE_CMS_ENABLED=true
```

5. Перезапустите локальный Vite. Для Vercel выполните один redeploy после изменения переменных. Это нужно только для подключения; обычная публикация статей больше не требует Git или сборки.
6. Откройте `/pl/admin`, войдите редактором, создайте тестовый черновик и проверьте предпросмотр. Публикация становится видна в `/pl/blog`, отдельной статье и динамической карте сайта. Будущая дата скрывает статью до её наступления.

## Проверка прав перед включением

- Без входа: видны только опубликованные статьи с наступившей датой. Черновик не должен открываться по прямой ссылке.
- Обычный пользователь Auth, которого нет в `prime_editors`: вход возможен, редактор недоступен, запись в posts и загрузка изображений запрещены RLS.
- Редактор: создание, сохранение, публикация, снятие с публикации, удаление и загрузка JPEG/PNG/WebP до 8 МБ.
- После выхода: редактор закрывается. Сессия хранится в sessionStorage текущей вкладки, не в публичном конфиге.

Политики доступа находятся в самой базе, а не только в интерфейсе. Изображения `blog-images` публичны: не загружайте частные фотографии клиентов или материалы без разрешения. Неиспользуемые изображения можно удалить через Storage в Supabase. Удаление статьи автоматически не удаляет общий файл, который может использоваться переводом.

## Публикация и переводы

Заполните заголовок, адрес, описание, автора, блоки текста, SEO и при необходимости обложку с alt. Доступны H2/H3, абзацы, **жирный текст**, ссылки, списки, изображения и CTA. HTML не выполняется.

Перевод создаётся отдельной статьёй с нужным языком и выбором исходной статьи в поле «Tłumaczenie artykułu». URL может отличаться. Hreflang и переключатель языка учитывают только реально опубликованные переводы. Если перевода нет, переключатель ведёт на список статей выбранного языка.

Серверные функции `api/blog.mjs` и `api/sitemap.mjs` читают только публичные статьи и обновляют SEO без пересборки сайта. Vercel включает HTML-оболочку через `includeFiles`. Локальный Vite показывает клиентские страницы; проверка серверных обработчиков выполняется отдельно командой `node --test scripts/server.test.mjs`.

## Границы проверки

Тесты с подменёнными ответами проверяют сценарии входа, отказа в правах, редактирования, ошибок, публикации и удаления. Они не доказывают применение политик в вашем реальном проекте. Финальный тест реального аккаунта и RLS выполняется после шагов выше.

Основа реализации: [Supabase Auth](https://supabase.com/docs/reference/javascript/auth-signinwithpassword), [Storage RLS](https://supabase.com/docs/guides/storage/security/access-control), [файлы в Vercel Functions](https://vercel.com/kb/guide/how-can-i-use-files-in-serverless-functions).
